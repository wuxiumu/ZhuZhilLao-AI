## 开场：FDE 的思维方式（25秒）

"大家好！今天给大家看一个项目——用代码复刻小时候的竹知了玩具。

但我想说的不是技术多牛，而是**FDE 工程师的思维方式**：

什么是 FDE？Full-stack Development Engineer，全栈开发工程师。但在我看来，FDE 不只是会写前后端，更重要的是：

1. **产品思维**：从用户需求出发，而不是从技术出发
2. **强落地**：快速把想法变成可体验的产品
3. **持续反馈**：每个版本都能验证假设，迭代优化

我用这个竹知了项目，完整展示了这个过程。"

---

## 第一幕：MVP 思维——最小可行产品（40秒）

### 产品思考

"第一个问题：如果要做竹知了的 Web 版，你会怎么做？

很多人的第一反应是：用 Three.js 做 3D，用物理引擎做真实模拟，用 React 做组件化...

但 FDE 的思维是：**先验证核心假设**。

核心假设是什么？用户想在网上甩竹知了，听到那声'哇哇'叫。

所以 MVP 只需要：

- 能甩起来（物理模拟）
- 能听到声音（音频播放）
- 打开手机就能玩（零门槛）

**不需要 3D，不需要框架，不需要复杂架构。**"

### 快速落地

"看看我是怎么落地的：

```javascript
// 单文件，零依赖
// 一个 HTML 搞定一切：物理、音频、渲染、UI
// 用户不需要 npm install，不需要构建，打开就能玩
```

一个 HTML 文件，2000 行代码，包含：

- 绳系质点物理模型
- Web Audio API 音频处理
- Canvas 2D 实时渲染
- 完整的游戏逻辑

**这就是强落地——用最小的成本，验证最核心的假设。**"

### 页面展示

"打开页面，长按屏幕画圈，就像这样甩起来...

（停顿2秒，让声音响起）

听到没？这就是小时候的味道。转得越快，声音越响。

**MVP 验证成功：用户确实想要这个体验。**"

## 第二幕：用户反馈驱动迭代（50秒）



### 持续反馈

"MVP 上线后，FDE 的工作不是结束，而是开始。

我会看数据、看反馈：

- 用户玩了多久？→ 发现：玩一会儿就腻了
- 用户希望有什么？→ 发现：想要更多声音

**这就是持续反馈——不是自己猜，而是让数据说话。**"

### 产品决策

"基于反馈，我做了第二个版本——声音 Meme 版。

产品决策：

- 问题：单一声音很快会腻
- 方案：多主题切换，增加可玩性
- 目标：延长用户停留时间

```javascript
// 主题系统：一个配置对象定义一个主题
const THEMES = [
  { id: 'bamboo', name: '竹知了', audioSrc: '...' },
  { id: 'ice', name: '冰块', audioSrc: '...' },
  { id: 'mouse', name: '鼠标', audioSrc: '...' }
  // ... 7个主题
];

// 切换主题：换声音 + 换配色 + 换背景
function setTheme(id) {
  activeTheme = THEMES.find(t => t.id === id);
  applyThemeUI();  // 整个UI跟着变
}
```

**7种声音主题，每个都有独立的配色和背景。**

（快速切换演示）

看到没？从竹知了到冰块，从鼠标到卷尺...

**这就是基于反馈的迭代——不是拍脑袋，而是解决问题。**"

## [可选] 2.5幕：技术选型的权衡（30秒）

> 如果想展示 FDE 的技术判断力

"这里有个技术选型的故事。

做主题系统时，我面临选择：

- 方案A：用 React + 状态管理，组件化开发
- 方案B：纯原生 JS，手动管理状态

FDE 的思维是：**技术选型服务于产品目标**。

产品目标是什么？

- 快速迭代：新增主题要快
- 零门槛：用户打开就能玩
- 易维护：代码要简单

最终选择方案B：纯原生 JS。

**为什么？因为 React 增加了构建步骤，违背了'打开就能玩'的目标。**

**FDE 不是技术越多越好，而是恰到好处。**"

## 第三幕：热点借势——产品增长思维（60秒）



### 产品洞察

"第二个版本上线后，继续看反馈：

- 用户是谁？→ 发现：大部分是程序员
- 他们关注什么？→ 发现：2025年最火的是 AI

**FDE 的产品嗅觉：热点 + 用户需求 = 增长机会。**

于是做了第三个版本——AI 公司版。

产品逻辑：

- 程序员都关注 AI 公司
- 企业文化语录是个'梗'
- 把这些做成可以'甩'的玩具，自带传播性"



### 强落地执行

"从想法到上线，我只用了两天。

为什么这么快？因为架构设计时就考虑了扩展性：

```javascript
// JSON 配置驱动：新增主题零代码
{
  "id": "openai",
  "name": "OpenAI",
  "quotes": [
    "AGI for the benefit of humanity",
    "We believe AI should be safe"
  ],
  "colors": {
    "accent": "#10a37f",
    "bg": ["#0a1028", "#0d3d2f", "#1a5c47"]
  }
}

// 动态加载：运行时读取配置
async function loadThemes() {
  THEMES = await Promise.all(
    themeIds.map(id => fetch(`configs/${id}.json`).then(r => r.json()))
  );
}
```

**新增一个主题，只需要一个 JSON 文件 + 一个 SVG logo。**

这就是**架构设计的前瞻性**——MVP 时就为未来的扩展留了空间。"

## 第四幕：技术为产品服务（40秒）



### 产品目标驱动技术决策

"FDE 的技术选型，永远服务于产品目标。

举个例子：为什么要做离线支持？

```javascript
// Service Worker：离线也能玩
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(response => {
      return response || fetch(event.request);
    })
  );
});
```

产品场景：

- 用户可能在地铁上玩，网络不好
- 用户可能想发给朋友，不想让对方装环境
- 用户可能只是想快速体验，不想等加载

**技术决策：离线支持 + 单文件部署 + 零依赖。**

**为什么？因为产品目标是'打开就能玩'。**"

### 性能优化也是产品体验

"再比如性能优化：

```javascript
// 离屏渲染：静态背景只画一次
function buildBgLayer() {
  const offscreen = document.createElement('canvas');
  // 画网格、星星、萤火虫...
  bgLayer = offscreen;
}

// 每帧只需要 drawImage，不用重新画
function draw() {
  ctx.drawImage(bgLayer, 0, 0);  // 快！
}
```

用户不会注意到你优化了性能，但他会觉得'这个页面好流畅'。

**性能优化不是炫技，是产品体验的一部分。**"

## 演示要点

1. **核心价值观**：每个段落都要回到 FDE 的三个特点
2. **产品优先**：技术是为产品服务的，不是反过来
3. **快速节奏**：每个版本 40-60 秒，不要拖沓
4. **数据驱动**：强调'看反馈'而不是'我觉得'
5. **完整闭环**：从问题 → 假设 → 落地 → 反馈 → 迭代
